# 상황 바꾸기 (판정 다시 부르기)

새 API 없이 기존 `/judge`, `/me/progress`를 사용한다.

1. A3에서 기존 신청 현황을 유지한 채 01부터 입력을 다시 진행한다. 로그인 회원의 저장 상태가 화면에 없으면 `GET /api/v1/me/progress`로 먼저 불러온다.
2. 12에서 새 입력 전체를 `POST /api/v1/judge`로 보낸다. 로그인은 불필요하며 판정 요청 자체는 저장 데이터를 바꾸지 않는다.
3. 로그인 회원은 새 profile과 병합한 services를 `PUT /api/v1/me/progress`로 저장한다. 같은 id의 기존 상태가 submitted·approved·in_use면 그 상태와 submitted_at을 유지한다. 새 판정 목록에서 빠진 서비스도 이 진행 상태라면 유지한다. 다른 서비스는 재판정 결과를 사용한다.

PUT은 전체 덮어쓰기이므로 프론트가 위 병합을 수행해야 한다. 기존 진행 상태를 apply/check/null로 덮어쓴 요청을 서버가 자동 복구하지 않는다. 명시적 상태 변경·초기화는 기존 계약대로 가능하다.

비로그인은 화면 상태만 갱신한다. judge 실패 시 저장을 호출하지 않고, 저장 실패 시 기존 보관 상태를 유지해 재시도한다. 요청·응답·오류 형식은 기존 두 API와 같다.
